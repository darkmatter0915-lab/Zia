# Rift Forge 0.10.0：角色解鎖與戰鬥體感改善

## 基線與選擇

2026-10-10 檢查的基線為 `69db17bcee3bb08a1f72cb96ee118aebaae875f3`。PR #11 已合併，部署流程 `36161592512` 成功。公開站的 27 個執行資源與該提交逐一符合 Git blob 雜湊；0.9.0 第二章「霜骸王庭」、六波、三種冰系敵人、斬刑者與女王均已發布。

本批保留兩章、戰鬥規則、舊角色與 `rift-forge.v1.*` 儲存空間。先增加「通關後有不同玩法可選」及修復配裝承接，再擴大關卡數量。2026-10-10 使用者審閱摘要後批准發布至原遊戲網址；以草稿 PR、CI、合併後 Pages 部署與正式資源雜湊核對確認上線，不以推送成功代替部署驗證。

## 本批可玩的變更

- 新角色「霜衛」：可靠通關紀錄解鎖。第一章以霜晶／毒棘起手；直接進第二章則以二階霜晶／毒棘／血珀起手。接球額外 +1 能量，鼓勵冰毒控制與回收循環。
- 霜環：100 能量，清彈、擊退 70，普通敵人 18／Boss 40 直接傷害，45% 減速 4 秒、8/秒毒傷 4 秒。鍊金行者維持原數值與起手配裝。
- 選角卡顯示起手、主動技、被動、鎖定條件與已選狀態；選擇偏好獨立保存。繼續存檔依當局角色，不會被標題選角覆蓋；承接第二章不換角色或配裝。
- 新增獨立六姿態霜衛圖集；霜環使用冰晶環形特效，閃避殘影使用新角色圖。沿用既有載入、失敗重試及內容雜湊流程。
- 修復第一章結算後關頁／重載遺失配裝：保存已結算的通關節點，標題可「承接第一章配裝」。獎勵只結算一次；切往第二章後回到正常戰鬥存檔。
- 修復 Boss 被脈衝擊退後讀檔強制回到原位；保留新版本合法戰鬥位置，只有缺少 Boss 身分的早期存檔使用原遷移位置。
- 升核卡顯示實際基礎直接傷害前後值與元素效果數值，明示不含刻印、鍛造或事件加成。
- 地面預警邊界納入既有玩家判定半徑（左右各 12），避免站在圖形外仍受傷的誤導；顯示攻擊名稱／倒數，Boss 出手前顯示蓄勢名稱。
- 精簡特效限制密集裝飾命中／電弧等爆發的繪製數量，保留所有敵彈、危險區、技能與預警。不改實際傷害或模擬上限。

## 存檔規則

`meta.unlockedCharacters` 記錄永久解鎖；舊 `wins > 0` 或 `chapter2Wins > 0` 可證明曾通關，遷移時解鎖霜衛。擊破一般怪物、抵達波次、擊殺中途 Boss、持有碎晶或高等級都不作為通關證據。舊進行中存檔沒有 `character` 時使用鍊金行者，保留等級、彈核、刻印、RNG 與章節。

通關節點只接受第一章、`phase: win`、`paid: true`，且已擊破 `bell`；其他不合法終局資料仍拒絕還原。不改 key 或清除玩家儲存空間。第二章通關沿用既有結算及重戰流程。

## 分階段擴充建議（尚未實作或核定）

| 階段 | 重點與可玩價值 | 進入下一階段前的條件 |
| --- | --- | --- |
| 本批 | 霜衛、選角解鎖、通關配裝保存、數值卡、可信預警 | 兩引擎回歸、手機布局與存檔遷移通過，使用者體驗確認 |
| 下一批：兩章差異與難度 | 第一章偏熔爐／反彈，第二章偏寒霜／回收的專屬事件與代價；可選挑戰詞綴，例「雙拍斬線」預告兩段攻擊、「護衛轉向」需要側牆破盾，提供相應資源／角色挑戰進度 | 每個詞綴有可理解對策、保留可躲避窗口；先驗證少量組合，不只加血量或換色 |
| 後續：第三章縱向切片 | 建議先做一段完整短章，主題可為雷暴機關區；新敵人角色分工包含架設導電點的支援怪、需改變反彈路徑的護衛、切換遮蔽路線的 Boss | 一段流程含進入／中途選擇／Boss／結算／存檔，通過後才擴到完整章；題材與數量由使用者再決定 |
| 再後續：可重玩進程 | 用可見成就解鎖更多機制角色；章節挑戰階級、精英攻擊組合、可重現的種子挑戰 | 每個角色有真實策略差異、關卡收益與難度可解釋，不以永久數值成長掩蓋不公平攻擊 |

優先順序是先做好可辨識攻擊與低負載，再增加密度；新增敵人必須回答「玩家要改變哪個決策」。目前第二章共享事件池是合理的下一批切入點。開場約 2 秒就可能升級會打斷操作學習，本批先改善資訊；延後首個升級需要固定種子與真人試玩評估，未直接改 XP 曲線。

## 驗證

詳細結果與畫面證據由本次本機驗證附錄記錄。自動化會以明確 QA 固定場景檢查視覺；這些畫面不冒充自然遊玩進度。瀏覽器尺寸模擬不能代表實體 iPhone 的多指觸控、耗電或 FPS。

可重現指令（repository 根目錄，Node 22.12+、Python 3）：

```sh
npm ci
node --test public/rift-forge/tests/engine.test.cjs
npm test
npm run build
npm run verify:dist
npx playwright install chromium webkit
npx playwright test -c playwright.rift.config.cjs
npx playwright test -c playwright.config.js
node scripts/rift-forge/simulate-characters.cjs
```

改動執行資源後先執行 `node scripts/rift-forge/stamp-release.mjs`；建置會檢查所有內容雜湊。授權發布版本為 0.10.0；保留所有既有儲存 key。

本機 `http://127.0.0.1:4187/rift-forge/` 是獨立 origin，不會讀取或覆蓋正式站存檔。既有通關解鎖遷移已由隔離瀏覽器 fixture 驗證；不要將本機新玩家的鎖定畫面誤認為正式站進度遺失。

角色模擬固定三個種子 `42 / 135 / 20261010`、`forge: 2 / ward: 2 / archive: 1` 基地升級及同一合法操作政策，不修改 HP、XP 或敵人狀態。這證明兩角色與承接流程能完成遊戲，不代表已做充分真人平衡評估；霜衛較容易累積技能、較偏生存控制，後續需真人試玩調整。

最初 108 項瀏覽器回歸有 1 項音效失敗。獨立探測確認此 Windows WebKit build 的 `AudioContext` 與 `webkitAudioContext` 均不存在，Chromium 則能建立、暫停與恢復音效。本批把畫面／模擬暫停與音效驗證分開：前者兩瀏覽器皆通過，後者 Chromium 通過、WebKit 僅在 API 缺席時明確略過。沒有關閉其他暫停斷言或聲稱 WebKit 音效已通過。

視覺檢查涵蓋六格霜衛透明圖集、桌面 1440×900、手機橫向 844×390、直向 390×844，以及選角鎖定／已解鎖／通關畫面。核對角色辨識、霜環、預警範圍與倒數、彈核資訊、選角按鈕和捲動區；截圖為明確固定 QA 場景。精簡模式另有回歸確認不會裁掉舊敵人的紅色閃電攻擊。

密集場景為 70 敵人、140 彈球、90 特效、70 狀態；最後一次 headless Canvas 繪製平均耗時為 Chromium 完整 42.76 ms／精簡 34.10 ms，WebKit 完整 53.13 ms／精簡 37.03 ms。這不是實機 FPS。兩次基線／修改版對照的分布重疊、雜訊大，不能宣稱穩定加速；目前可驗證的是裝飾繪製有上限且保留威脅資訊。原始量測已隨審閱包附上。

尚未執行實體 iPhone / Android 多指、真實 Safari 音效、長時間發熱耗電或低階手機 FPS 測試。以上為合併前本機驗證紀錄；正式發布結果另以 GitHub PR、Actions 部署與線上核對為準。後續章節工作尚未實作或核定。

發布前 GitHub CI 另外發現 Windows `core.autocrlf` 使工作檔與提交檔換行不同，造成入口資源雜湊不符。本批以遊戲目錄的 `.gitattributes` 固定 HTML／JS／CSS／JSON 為 LF，WebP 保持二進位；重新產生入口雜湊，並以提交暫存區的原始位元核對，確保 Windows 與 Linux CI 使用相同資源內容。
